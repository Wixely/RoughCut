# CupriFace 0.41.0 upgrade and diagnostics evidence

- Date: 2026-10-09
- Platform: Windows 10 Enterprise, .NET SDK 10.0.302, CupriFace 0.41.0
- Scope: the desktop review window's UI library, moved from the vendored 0.26.1 packages to 0.41.0 restored from GitHub Packages, and the three silently-ignored CSS declarations that CupriFace's own checker found
- Supports: [decision 0027](../decisions/0027-cupriface-from-the-feed.md)

`92 passed; 0 failed` with `--media --cli --desktop --mcp`. One check is new.

## The upgrade needed no source changes

0.26.1 and 0.41.0 are fifteen minor releases apart. CupriFace's release notes carry exactly one `### Breaking` section in that file, under v0.2.11 — far below 0.26.1 — and the v0.41.0 release carries only `Added` and `Fixed`, so nothing in the range changes an API this project calls. The desktop project builds against 0.41.0 in both Debug and Release with no edit to any `.cs` file and no new warning, and the whole gate passes, including the headless layout checks that measure rendered boxes (the review panel's contents staying inside it, the rendition picker's controls staying inside the card).

The packages are now restored from `https://nuget.pkg.github.com/Wixely/index.json`, which is where CupriFace is published; it is not on nuget.org. The three `.nupkg` files that were vendored under `vendor/nuget` are gone. The feed is verified rather than trusted: each restored package was hashed and compared with the same file downloaded from the GitHub release, and all three match exactly:

- `CupriFace.0.41.0.nupkg`: `57053f7af8504974fa80ffd894805f43dabbf0d01d4de34e3fdb4078f1572d28`
- `CupriFace.Media.0.41.0.nupkg`: `ab70531b3d8f86a843922ae17accc88829f8dd2daef8e291327873321f24f3b4`
- `CupriFace.Shell.0.41.0.nupkg`: `448d7f307c64fde92e594b1cc69172640b8e78f6689462ccf458417fbc3f53f6`

Package metadata identifies repository commit `a331aace00f27d1e84565250ba4bd20aa926852a` and MIT licensing.

`packageSourceMapping` in `NuGet.config` had to name the feed for the `CupriFace*` pattern. Until it did, restore refused the packages and said so, which is also why the vendored folder had been working only by accident: with `*` mapped to nuget.org alone, the project's own `RestoreAdditionalProjectSources` folder was never considered, and 0.26.1 resolved out of the machine's global package cache rather than out of `vendor/nuget`. A contributor restoring from a clean cache would not have got the vendored copies either.

## What 0.41.0 changes here: nothing, checked rather than assumed

Its two entries both touch things this project could have cared about, and neither moves it.

`visibility: hidden` is now implemented — until 0.41.0 the property was parsed by nothing, reported by `CF0050` as ignored, and the element stayed fully painted and fully operable. An app relying on it would change behaviour on this upgrade. This window never used it: the review markup hides things with a `hidden` class that sets `display: none`, and `visibility` appears nowhere in the desktop sources.

`CF0074`, the flush-rounded-boxes check added in 0.40.0, was narrowed to skip boxes painted somewhere other than where they were laid out. That only removes findings, and this document had none from it at either version.

## Three CSS declarations were being ignored

`CupriDoctor.Check` reads its checks from the engine rather than from a hand-written table of what is supported, and the engine ignores a property it does not implement instead of throwing. All three findings were real, and two were a bug a person would have blamed on an unfinished layout:

- **`.transcript` and `.recent-list` never scrolled.** Both were written `overflow-y:auto`. The engine styles `overflow`, not the `-y` longhand, so both declarations were dropped and both lists overflowed instead of scrolling — the transcript being the one list in the window that is always longer than its panel. `overflow:auto` is supported and maps to a scrolling box; the horizontal axis is clipped with it, which is what these columns want anyway.
- **`button { font:inherit }` did nothing.** The `font` shorthand is not styled. Nothing had to replace it: the engine applies no user-agent font to `button` — there is no `button` case among its element defaults — so the font already inherits from the parent chain. The longhand spelling would have been actively worse, because the resolver takes `font-family`'s value literally and would have set the family to the name `inherit`.

The doctor reports one finding per property, so the second `overflow-y` only appeared after the first was fixed.

## The check now runs on every gate

The new check runs the doctor over the **populated** review surface — a loaded session, a document created and refreshed, so every `data-repeat` holds real rows — rather than the launcher's empty model, which cannot exercise the checks that need content. It reports no findings at any severity, including the advisory `Info` level. Errors and warnings fail the check; `Info` is advisory and does not, which is how the library's own release notes describe that level.

## Limitations

The window was not opened by a person in this slice, so the two lists that now scroll have not been scrolled by hand: the fix is the engine accepting a property it previously discarded, measured by the gate, not an observed drag. Nothing here revisits what the fifteen releases added — the upgrade was taken for the current UI, and new CupriFace capabilities remain unexamined.
