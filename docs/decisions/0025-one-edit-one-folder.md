# 0025: An edit is one folder

- Date: 2026-09-27
- Status: Accepted for the desktop and MCP project-creation paths
- Refines: the portable-project layout accepted in [0002](0002-mvp-foundation.md)

## Context

A project file references its media by a relative path, because a portable project must be movable. But nothing made the media live beside the project, and the two creation paths disagreed:

- A URL acquisition wrote a folder named after the moment it happened — `2026-09-27-143015` — holding the media, the project and its assets. Tidy, but named after a timestamp nobody recognises.
- A local video got a project file written **beside the video**, wherever that was: a `.json` dropped into somebody's Downloads folder or camera roll, with `assets/` appearing next to unrelated files. Deleting the edit meant knowing which of those files belonged to it.

The instruction that settled it: all files related to the edit should go in one folder, either chosen or generated by name in a tidy location, and that folder should hold everything including the project file.

## Decision

One edit is one directory. It holds the media, `project.json`, and every asset the project generates — captions, images, previews — so the whole edit can be moved, copied, backed up or deleted as a single thing, and its stored paths stay portable because the media is genuinely inside it.

`ProjectFolder` owns the naming, because a name taken from a video title is not automatically a name a filesystem accepts: characters are reduced, runs of spaces collapse, trailing dots and spaces go, the result is capped at 80 characters, and a reserved device name such as `nul` becomes `nul-project`. An existing folder is never written into — `Fixture title` becomes `Fixture title-2` — so asking for the same video twice keeps both edits.

A local video is **copied** into the edit folder, never moved: the person's own file stays exactly where it was, and the copy is what the project fingerprints, so a later change to the original cannot invalidate the edit. The copy reports progress and is written under a temporary name until complete, so a cancelled copy leaves neither a whole file nor a fragment that could be mistaken for the source.

Where the folder goes is the caller's choice. The desktop generates one under its projects root — named from the video's own title for a URL, or the file name for a local video — shows it, and lets a person edit it or pick a location with the platform's folder browser. `roughcut_create_project_folder` is the same operation for a headless caller, both paths workspace-relative.

## Consequences

- Deleting an edit is deleting one folder. Finding an edit is finding one folder with a recognisable name.
- A local video now exists twice while the edit does. That is a deliberate cost: it buys portable paths, a stable fingerprint and a self-contained folder. A person who does not want the copy can still point RoughCut at a project beside their video, which the older path continues to produce.
- Two creation paths remain: `CreateProjectAsync` for media already where the edit should live, and `CreateProjectFolderAsync` when it is not. The second is what both the window and new MCP callers should use.
- Folder names come from source titles, which are untrusted text. They are reduced to a safe subset rather than trusted, and never used as a path without going through `ProjectFolder`.

## Evidence

`docs/evidence/2026-09-27-desktop-acquisition-and-export.md`. The suite covers the naming reduction including reserved names and over-long titles, the unused-name search, a copy that reports rising progress and leaves nothing behind when cancelled, and a desktop edit created from a local video whose folder holds both the project and its own copy of the video with the original untouched.

## Review trigger

Before adding a creation path that writes a project outside its media's folder, or if the duplicate copy becomes a problem for large sources — in which case consider a link or a recorded external reference, and say plainly what that costs in portability.
